* Dota 2 Counter-Pick — Authentication & Authorization Demo

A full-stack web app where users browse Dota 2 heroes, suggest counter-picks, discuss matchups, and vote on comments. Built to demonstrate JWT auth, role/claims-based authorization, OAuth 2.0, rate limiting, and ASP.NET Core Identity.

** Features
- Hero grid with search + attribute filter (Str/Agi/Int/Universal) — 127 heroes seeded from OpenDota API
- JWT auth with access (15 min) + refresh (7 days) tokens; auto-refresh on 401
- Role-based: Admin role manages users
- Claims-based policies: CanComment, CanDeleteAnyComment, VerifiedAccount (from OAuth)
- Counter suggestions — logged-in users propose counters for hero matchups
- Comment + like system on each counter pair; most-liked rises to top
- Comment ownership — Edit/Delete buttons only for the author (frontend + resource-based authorization)
- Admin panel — user table with delete (protected: cannot delete self or seed "admin" user)
- OAuth 2.0 login via Google / Microsoft (conditional — skipped if secrets not set)
- Rate limiting: 3/10min anonymous, 100/min authenticated on hero endpoints; 5/min/IP on login
- 429 detection with toast notification
- Failed login and token-theft logging via ILogger

** Entity Relationships

#+begin_src text
Hero ──┬── CounterSuggestion.HeroId        (Restrict delete)
       └── CounterSuggestion.CounterHeroId (Restrict delete)

CounterSuggestion ──┬── Comment.CounterSuggestionId (Cascade delete)
                    └── SuggestedById → IdentityUser.Id (string, no FK)

Comment ──┬── SuggestionLike.CommentId (Cascade delete)
          └── UserId → IdentityUser.Id (string, no FK)
          └── Unique index: (CommentId, UserId) on SuggestionLike

RefreshToken.Token → unique index
RefreshToken.UserId → IdentityUser.Id (string, no FK)
#+end_src

- `Hero.Roles` is a comma-separated string (not a join table) — pragmatic for a demo.
- `LikeCount` on Comment is denormalized (stored + counted in SuggestionLike table) for fast reads.
- No hard FK relationships to `IdentityUser` — UserId is stored as a plain string in Comment, CounterSuggestion, SuggestionLike, and RefreshToken.

** Auth Flow

#+begin_src text
── Password Login ──
  POST /auth/login { username, password }
    → UserManager.FindByNameAsync
    → UserManager.CheckPasswordAsync
    → TokenService.GenerateAccessToken (claims: NameIdentifier, Name, Email, roles)
    → GenerateRefreshToken (64 random bytes, Base64)
    → Save RefreshToken to DB (ExpiresAt = UtcNow + 7 days)
    → Return { accessToken, refreshToken, expiresAt }
    → Client stores both in localStorage
    → Every apiFetch() sets Authorization: Bearer <accessToken>
    → On 401: tryRefresh() POSTs /auth/refresh → new token pair → retry original request
    → On 429: showToast("Rate limited — slow down!")

── OAuth Login (Google/Microsoft) ──
  GET /auth/external-login/{provider}
    → Challenge(properties, provider) → redirects to Google/MS consent page
    → User approves → redirects to /auth/external-callback
    → GetExternalLoginInfoAsync
    → ExternalLoginSignInAsync (existing link?)
    → If not linked: FindByEmail → CreateAsync + AddLoginAsync
    → Add Claim("ExternalLogin", "true") → satisfies VerifiedAccount policy
    → Redirect to /login.html#access_token=...&refresh_token=...

── Token Refresh ──
  POST /auth/refresh { refreshToken }
    → Find token in DB
    → Check: exists? revoked? expired?
    → If revoked → revoke ALL user tokens (theft detection)
    → Mark old token as revoked
    → Generate new access + refresh tokens
    → Save new RefreshToken to DB
    → Return new pair

── Token Revocation ──
  POST /auth/revoke { refreshToken }
    → Find token in DB → mark IsRevoked = true
    → (Client can call this on logout)
#+end_src

** Rate Limiting

| Policy       | Partition key         | Window   | Permits | Applied to                                  |
|--------------+-----------------------+----------+---------+---------------------------------------------|
| SearchLimit  | RemoteIp (anon)       | 10 min   | 3       | GET /api/heroes, GET /api/heroes/{id}       |
| SearchLimit  | UserId claim (auth)   | 1 min    | 100     | GET /api/heroes, GET /api/heroes/{id}       |
| LoginLimit   | RemoteIp              | 1 min    | 5       | POST /auth/login, POST /auth/register       |

- `SegmentsPerWindow = 1` → behaves as fixed window, not truly sliding.
- Static files (wwwroot/) are NOT rate-limited.

** Authorization Policies

| Policy String          | Requirement                              | Used On                          |
|-----------------------+------------------------------------------+----------------------------------|
| CanComment            | Authenticated user                       | (declared, not referenced)       |
| CanDeleteAnyComment   | Admin role                               | (declared, not referenced)       |
| VerifiedAccount       | Claim("ExternalLogin", "true")           | (declared, not referenced)       |
| OwnsComment           | CommentOwnerRequirement + CommentOwnerHandler | PUT/DELETE /api/comments/{id} |

CommentOwnerHandler:
  - Reads ClaimTypes.NameIdentifier from JWT
  - Compares to Comment.UserId
  - Succeeds only if they match (no admin override)

#+begin_src sh

** How to Use

*** 1. Browse heroes (anonymous)
- Home (/) shows all 127 heroes in a responsive grid (6 cols on large screens → 2 cols on mobile).
- Search bar filters by localized name clientside.
- Attribute buttons filter by primary attribute (Strength/Agility/Intelligence/Universal).
  Universal heroes have primaryAttr = "all" (per OpenDota API).
- Hero count updates live as you filter.
- Status: anonymous → 3 hero page loads per 10 min; toast on 429.

*** 2. View hero details & counters
- Click any hero → hero.html?id={id}
- Shows: large portrait, name, attribute badge, attack type, role tags.
- Below: counter suggestions — each shows counter hero icon, name, top comment (most liked), and "Discuss" link with comment count.
- The "Suggest a Counter" form appears only when logged in.
- Seed data: 2 random counter suggestions per hero, posted by admin.

*** 3. Register
- Login (top-right) → /login.html → Register tab.
- Fields: username (3-50 chars), email, password (6-100 chars).
- On success: immediately logged in (JWT stored, navbar shows username + Logout).
- Rate-limited: same 5/min/IP as login.

*** 4. Login
- /login.html → fields: username, password.
- Seed admin: admin / Dota2@Secure2024!
- On success: JWT stored, redirected to heroes page.
- If Google/MS OAuth configured: buttons on login page redirect to provider consent.

*** 5. Add counter suggestions
- While viewing a hero page and logged in → "Suggest a Counter" form.
- Select counter hero (dropdown excludes current hero), type reason, click Submit.
- New suggestion appears immediately (no moderation).

*** 6. Discuss & vote
- Click "Discuss (N)" on any counter → /discussion.html?suggestionId={id}.
- Comments list sorted by like count (desc), then date (desc).
- Each comment shows: username, date, content, like button (♥ + count).
- Post: type in input field, click Post.
- Like: click ♥ on any comment — toggles like/unlike. Count updates live.
- Edit own: click Edit → inline input replaces content → Save or Cancel.
- Delete own: click Delete → confirm dialog → removed.

*** 7. Admin panel
- Login as admin → Admin link appears in navbar → /admin.html.
- Table: username, email, lockout status, failed login count.
- Delete: click Delete → confirm. Cannot delete yourself or the seed "admin" user.
  (Client-side: button disabled for "admin". Server-side: returns 400.)

*** 8. Token refresh (automatic)
- Access tokens expire in 15 min.
- On any 401 API response, apiFetch() tries tryRefresh() once.
  - POST /auth/refresh with stored refresh token.
  - If success: new tokens stored, original request retried.
  - If fail: tokens cleared, redirect to /login.html.
- Refresh tokens expire in 7 days or can be revoked server-side.

** Implementation Notes
- OAuth providers are registered conditionally (skip if ClientId/ClientSecret not in user-secrets).
- External login creates local IdentityUser on first visit (matched by email) and adds "ExternalLogin" claim.
- Rate limiter SegmentsPerWindow=1 → fixed window behavior (resets fully at window boundary).
- CounterSuggestions use two FKs to Hero (HeroId + CounterHeroId) with Restrict delete.
- Comment likes: unique index on (CommentId, UserId), denormalized LikeCount on Comment.
- SuggestionLike stores *comment* likes, not suggestion likes — slightly misleading name.
- CommentsController GET loads ALL IdentityUsers into memory for name resolution (not scalable).
- AddCommentDto / AddCounterDto / UpdateCommentDto are defined inline in controller files (not in Core/DTOs).
- No duplicate-counter-suggestion guard — same user can suggest the same pair multiple times.
- RefreshToken has no navigation to IdentityUser — UserId is a plain string.
- Token visible in URL fragment on OAuth callback (accepted learning-project limitation).
