* polymorphism example
#+begin_src csharp
class Animal

    public virtual void MakeSound() {Console.WriteLine("Animal sound");}
}

class Dog : Animal
{
    public override void MakeSound() {Console.WriteLine("Woof");}
}
class Cat : Animal
{
    public override void MakeSound() {Console.WriteLine("Meow");}
}

a3.MakeSound(); //Animal sound
#+end_src

Even though both a1,a2 variables are =Animal=, the correct child method
executes.

* Access Modifiers
Access modifiers control visibility. {depending on what you need}

| Modifier             | Accessible From                  |
|----------------------+----------------------------------|
| =public=             | Everywhere                       |
| =private=            | Inside same class only           |
| =protected=          | Same class + derived classes     |
| =internal=           | Same project/assembly            |
| =protected internal= | Derived classes OR same assembly |

** Real Use Cases
- =private=
  - Internal calculations
  - Sensitive data
  - Helper methods
- =protected=
  - Base class logic for child classes
- =public=
  - APIs exposed to other code
- =internal=
  - Shared project utilities

Start restrictive, then open access only if needed. Typical order: > 1.
=private= 2. =protected= 3. =internal= 4. =public= Good developers
usually avoid making everything =public=.

** finally

#+begin_quote
=finally= Used for cleanup: * closing files * database connections *
network sockets
#+end_quote

The =finally= block runs *always*: - whether an error happened - or not

commonly used for: - closing files - releasing database connections -
cleaning resources

Modern C# way: =using= automatically closes the file for you.

*** Example:
=csharp id="gajglf" FileStream file = null; try {     file = File.OpenRead("data.txt"); } catch (Exception ex) {     Console.WriteLine(ex.Message); } finally {     file?.Close(); }=
​#### Meaning of =?.= *null conditional operator*.

=file?.Close();=

means: > "If =file= is NOT null, call =Close()=."

Equivalent old-style code: =if (file != null){    file.Close();}=

* task OOP applied
** about
THIS APP TAKES SOME USER DATA {NAME, AGE, PROFESSION} + SOME MORE
QUESTIONS FOR CLARITY THEN RECOMMENDS SOME USEFUL APP BASED ON
INTERESTS/THOSE ANSWERS

** The app uses almost every OOP concept:
1. Encapsulation --- User hides _name, _age, _profession as private
   fields, exposing them only via init-only properties. The Answers list
   is protected, so only derived classes can modify it.

2. Inheritance: All 7 persona classes inherit from User: Student,
   Teacher, Developer, Designer, Writer, Artist, Manager reusing its
   properties and constructor via : base(name, age, profession).

3. Polymorphism --- both AskFollowUpQuestions() and GetRecommendations()
   are virtual; each subclass overrides them.
   RecommendationEngine.Process(User user) calls these methods on a User
   reference, and C# goes to the correct runtime type accordingly

4. Access Modifiers:

   - private fields,
   - pubic properties
   - protected =Answers= list
   - public methods

5. Constructors: Base constructor with validation, derived constructors
   chaining with : base(name, age, profession)

6. Properties: { get; init; }, sometimes with validation

7. Abstraction --- UserFactory.Create() abstracts away which proper
   class gets selected/created.
